# 14 · 一次修复不会把「修之前的那一版」收回

R15 判出 `origin/main..HEAD` 内有 8 处命中（4 个 blob、落在 3 个文件上），**全部只存在于中间提交**。
树闸（看 HEAD 树）与信息闸（看每条 message）这时都是绿的 —— 因为**修过之后**，树和信息确实干净了。
但一次 push 送走的是**三样**：树、每条 message、以及该范围内**每一个 blob**（含中间态）。
前两样已经被修好，第三样没有：**修复写得再干净，也不会把修之前的那一版从待推对象集里收回。**

## 观测（都能本机重跑）

- 范围 `origin/main..HEAD`（11 个提交）：树 `files=47 LEAKS=0 rc=0`；信息 `commits=11 LEAKS=0 rc=0`；
  对象内容 `objects=106 blobs=48 LEAKS=8 rc=1`。
- 8 处命中 = **4 个 blob**：`findings/05-…md` 两版、`findings/08-…md` 一版、`verify/ledger_discipline.py` 一版；
  涉及提交 `5c05449 / 48c1de4 / fe06154 / bb91e2c / 55a40d9`（正是 R10/R11 两次「去泄漏」提交留下的前一版）。
- 命中形态：词表词 5 处、盘符路径 3 处（本闸默认打码、样本只给长度；要看字面用 `git cat-file blob <sha>`）。
- 这 4 个 blob 全部落在「只存在于中间提交」的那批里 —— 树闸**结构性**看不见（不是漏扫，是范围不同）。

## 处置（本轮做的）

重写这批**未推**提交的树：凡某路径的 blob ∈ 脏集合，就把该路径换成 **HEAD 同路径的 blob**（= 它后来的干净版本）。
逐条 `commit-tree` 重建父链；作者、提交者、时间、正文**逐字节保留**；最终 HEAD 的**树零改动**，只换中间态。

- 旧链 11 个提交 → 新链 11 个提交；旧 HEAD `d256e58ea8eb` → 新 HEAD `ad14dcaf1c06`。
- 树 sha `21bbb8c55153` 前后相同；`git diff --stat <旧HEAD> <新HEAD>` 为空；工作区干净。
- 4 个脏 blob 在 `origin/main..HEAD` 内 **可达 = 0**（逐个 `git rev-list --objects | grep -c`）。
- 抽 4 条提交比对正文 sha256 前缀：`d256e58ea8eb/ad14dcaf1c06`、`727e81de7f02/61f2d1216ba8`、
  `55a40d9e641d/89d44426eda2`、`5c0544931911/8bb43b462951` —— 四对**全同**。
- 事后四道闸（新鲜跑）：树 `rc=0 LEAKS=0`；信息 `rc=0 commits=11`；对象 `rc=0 blobs=44`；台账纪律 `rc=0 PASS=3/3`。

## 让这件事「能失败」的那部分（不然等于没验）

自证夹具：仓外 `EXCURSION_10H/_r16_selftest.py`，本轮实跑 **17 项全绿**。

- **A 正常处置**：同一夹具上先证「树闸 rc=0 而对象闸 rc=1」（这正是这道闸存在的理由），处置后对象闸 1→0；
  且最终树零改动、提交条数不变、每条 message 与 author/committer 时间**逐字节相同**。
- **B 拒绝**：脏路径在 HEAD 已被删除（没有「后来的干净版本」）→ 工具必须 rc=1、ref 不动、闸仍红。
- **C 对照**：只 dry-run → ref 不动、闸仍然红 —— 证明 A 的绿来自那次 ref 更新，不是复跑带来的。
- 夹具当场抓出**两个真 bug**：① `update-ref` 拿到的是上游短名 `origin/main`（不是可写的分支 ref，写必然失败）；
  ② 一个把「绿了才算过」写成「红了就什么都不做」的空转分支。**不摆夹具，这两个都不会被发现。**

## 护栏

- 默认 dry-run；`--apply` 才动 ref。`update-ref <ref> <new> <old>` 带旧值做 CAS。
- 写 ref 前必须证 `diff --stat` 为空且树 sha 相同；写后立刻复跑四道闸，任一非 0 **自动回滚**。
- **不 push、不 gc。** 推送 = 对外发布，须授权人批。

## 已知未覆盖（不许写成「清干净了」）

- **不可达对象仍在**：重写前的旧提交与那 4 个脏 blob 还躺在本地对象库与 reflog 里（`git cat-file -t` 仍取得到）。
  这是**本机**风险，不是发布面；本轮没做 gc，所以不写「已清除」。
- 不含 tag / 分支名 / reflog / stash / notes / PR 正文；不含二进制 blob。
- **语义代价要写清**：把中间提交的那一版换成 HEAD 的那一版，等于让那条提交「提前显示」了后来才写的正文。
  最终树没变，可审计性由本文件与本轮台账记录补回 —— 但它确实是**改历史**，不是「没发生过」。
- 「远程此刻的 main 是否被别处改写」本闸不判（那是 `bridge_landed` 的活，而那双腿仍未通）。
- 新链的提交哈希全部变了 ⇒ 旧记录里的 `d256e58` 已不是 HEAD，落点改为 `ad14dcaf1c06`。
