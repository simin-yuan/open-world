# 10 · 闸跑在发布之后，等于没有闸

**观测**（本机可重跑；原始输出存档在本机 `EXCURSION_10H/evidence/t10_*`，不进本仓）

| 事实 | 怎么得的 |
|---|---|
| 自动发布路径 = `tools/export.py` → `git add -A` → `commit` → `git push origin main`，每天两次 | 读本机 cron job 入口脚本（不进公开仓，路径见 `_local/wiring.json` 同族位置） |
| **这条路径上没有任何隐私闸调用** | 同上，全文 grep：无 `leakscan` |
| 唯一的 `leakscan` 调用点在本仓 `.github/workflows/freshness.yml`，触发条件是 `on: push` | 读 workflow |
| ⇒ 实际顺序是「**先 push 到公开仓 → GitHub 再跑闸**」 | 由上两条推出 |
| 公开仓内容永久可检索（一次漏不可回改） | `findings/09` 已记 |
| 本机 `.git/hooks/` 只有 `*.sample`；`core.hooksPath` 未设 | `ls .git/hooks/` + `git config --local --list` |
| 接闸后，真台账在沙箱里跑导出 `rc=0`，闸 `LEAKS=0`（files=35） | `_t10_realpath.py`（normal 与 PATH 剥空各一次） |
| 本仓词表只有 2 词 | `python verify/leakscan.py` → `terms=2` |

**形状**：这条和本仓已记的 06/07/08/09 **不是同一条**。那几条都是「判据测的**范围** ≠ 它宣称的范围」；
这一条是「判据的**位置** ≠ 它要拦的**那一刻**」。位置错了，判据再准也没用 —— 只能出尸检报告：
它读得到，但读得**太晚**。

与 `findings/06`（提过一次 ≠ 交付过）也不同：那条问「有没有做」，这条问「做在**哪一步**」。

**修法**（`tools/export.py` + `verify/selftest_export_gate.py`）

- 在 `tools/export.py` 末尾加 `privacy_gate()`：**进程内**调 `verify/leakscan.py` 的 `scan(REPO)`，
  非 0 就打印命中 + `EXPORT_REFUSED` + `return 1`。上一级 job 见 `rc≠0` 即走 `fail()`
  → **不提交、不推送、推飞书**。
- **为什么放这里**：这是发布路径上最后一段属于本仓的代码，紧接着就是 `add/commit/push`。
  放这里还有一个副作用是好的：**进程内调用不靠 PATH**，cron 环境没有 PATH 也照样跑。
- **为什么 fail-closed**：桥停是**可逆**的，发布是**不可逆**的。宁可桥停一天，不可发一次泄漏。
- **`UNDECIDABLE`（词表读不到）也算拦下**：不许把「没查」洗成「干净」。实测（自证 C 用例）：
  去掉词表 → 闸 `rc=2` → 导出 `rc=1`。

**接线的自证**（`verify/selftest_export_gate.py`，10/10 绿；已加进 CI 步骤）

闸自己有自证（`selftest_leakscan.py`），但**接线**是另一件事 —— 一个接错位置的闸和根本没有闸，
从外面看长得一模一样。这份自证只问一件事：导出工具**会不会因为闸红而拒绝产出**。

| # | 用例 | 期望 | 实测 |
|---|---|---|---|
| A | 干净沙箱 + **自造**词表 | 导出 `rc=0` 且 stdout 有闸摘要（跑过 ≠ 静默） | PASS |
| B | 沙箱里植入命中串与盘符路径 | 导出 `rc=1`、点名命中文件、措辞写明「拒绝产出」 | PASS |
| C | 沙箱里**去掉词表** | 导出 `rc=1`（没查 ≠ 干净） | PASS |
| D | **PATH 剥空**下重跑 A | 仍 `rc=0`（cron 无 PATH 的形态） | PASS |

**自证会红吗**（`_t10_falsify.py`，4/4：把接线改坏，自证必须跟着红）

| 探针 | 期望 | 实测 |
|---|---|---|
| BASE 未变异（真仓） | 自证 10/10 绿 | `rc=0` |
| M1 `if grc != 0:` → `if False:`（闸红也不拦） | 自证红 | `rc=1`，6/10 |
| M2 `scan()` → `(0, [])`（闸恒绿） | 自证红 | `rc=1`，3/10 |
| M3 `grc = privacy_gate()` → `grc = 0`（根本不算） | 自证红 | `rc=1`，3/10 |

**这条自证自己被抓了一次**（值得单记）：最初把坏样本**写成字面**放在脚本里，结果沙箱 A 用例
`rc=1`、`LEAKS=2` —— 因为这份自证**自己也在被扫的那棵树里**，闸于是拒绝发布它自己。
改成拼接构造，并把这条做成机器检查（`no_literal_sample_in_source()`）。
这正是 `findings/09` 的同一条在另一处重演：**写检查的东西，自己得再被检查一次。**
代价要说清：拼接恰是本闸**拦不住**的写法之一（已知盲区）。这里用它不是为了绕门，是因为夹具
必须落在扫描范围内（否则测不到接线）、又不许让扫描器命中自己 —— 只有这一条出路。

**它测什么、不测什么**

| 覆盖 | **不覆盖** |
|---|---|
| 自动发布路径（每天 2 次）在 `commit/push` **之前** | **手动提交**这条门：本机 `.git/hooks/` 为空，`findings/08` 那次泄漏正是手动 commit 进去的 —— 本轮只记不做 |
| 整棵工作树（`files=35`），口径 = **将被 push 的那份内容** | **git 历史里的 blob**（提交后删掉的文件仍永久可检索）：闸只看树，不看历史 |
| 进程内调用，PATH 剥空实测跑得通 | 图片/二进制里嵌的信息；拼音/缩写/语义换写（`findings/09` 已列未知） |
| CI 里跑同一份自证（`.github/workflows/freshness.yml` 新增一步） | 该步的 **Linux 腿本机无法预跑** —— 下一次推送是它的第一次真实检验 |

**未证实**（不写成「没有」）：历史 blob 有没有泄漏 —— **没扫，不知道**；手动提交这条路 —— **仍是开的**。

**边界**：未加域名、未花钱、未注册平台、**未推远程**（推送 = 对外发布，须授权人批）；
未改 `check.py` 判据、未改任何阈值、未动 `_local/` 词表；**未改导出 job 本身**（那是桥）——
本轮改的是**本仓自己的** `tools/export.py`，桥只是照原样调用它。
