## 三条腿各自的问题

### 桥（对外那条输出腿）

- 远程最后一次收到是 **09-28 21:20**；09-29 09:20 那次排定导出的推送**挂死**（findings/11
  当天上午的观测）。到当晚恢复时，本地积压 **13 个提交**，最老一个 09-29 04:41:56（16.5h）。
- 处置按 findings/11「处置」一节落地：取凭据这一步改成非交互、拿不到就**立刻失败**；
  超时不再是摆设（输出落文件、按**整棵进程树**回收）；并且**成功判据改成回读远程 ref**
  —— `git push` 返回 0 只证明「我发过」，不证明「它到了」。
- 恢复后**本仓自己的判据**（`verify/bridge_landed.py`）当场复算：`status=LANDED rc=0`。

### 决策腿（这一次最重的发现）

三个**各自独立**的静默失效，后果都指向同一件事：**规则题上线以来一次预测都没产出来过**
（O6 是它的证据）。

- **(a) 取 JSON 的函数在格式良好的答复上取错了对象。** 它从后往前找最后一个 `{` 到最后一个 `}`，
  于是在 `{"answers":[{"i":0,"p":0.99},…]}` 上取到的是**最里面**那个 `{"i":5,"p":0.01}`。
  后果：每道题都判成「模型漏答」→ 整场静默转弃权，而**账面上看不出是脚本把答案扔了**。
- **(b) 模型偶发的简写形状让整个触发崩掉。** 答复写成 `{"0":0.6}`（值是概率本身）时，
  解析里一句 `dict(0.6, i="0")` 抛 TypeError 一路冒到顶 —— 触发终止，**连一行账都不落**。
  O7 里那三场空白就是这个形状：既没有弃权行、也没有批次行，停摆完全不可见。
- **(c) 正文为空时回退去读「思考」字段。** 那里常常只含系统提示里的**样例** JSON，
  解析它等于可能把样例当答案（比失败更隐蔽）；而额度被思考吃满时它根本不是答案。

外加一处收口缺口（O8）：模型通道不通那条路径**只写弃权行、不写批次收口行**，
于是这一窗到期的题凭空消失——对外那条闸看不见它们。脚本自己的注释写着「漏答不允许」，
而失败路径恰好产出了漏答。

### 处置（都带可重跑的判据）

- 取 JSON 改成：从每个 `{` 起做 `raw_decode` 取**最长合法对象**，带契约字段的那个优先 →
  单测 **6/6**；同一路径实跑：**6 题 → 6 条预测，批次 `answered=6 missing=0`**。
- 收不下的形状**退回错误**而不是抛异常；调用点整体接住异常 → 仍走正常失败路径落账。
- 只认正文，不回退思考字段；额度 1500 → 4000，并给「正文为空」一个**说得出名字**的错误。
- 批次收口补齐：模型通道不通时也写批次行，把到期题全列进 `missing`。

## 边界

- **09-27 那一批 `due=4 missing=4` 的历史行没有被改动。** 它是真的漏答，闸红得有道理。
  但它属于「已记录的**历史**缺陷」，而当前判据不区分「历史缺陷」与「正在发生的失败」。
  一条永远红、永远在说同一件旧事的判据，会同时丢掉对新故障的灵敏度。
  怎么处置由判据的所有者定；本文只把它标出来，不代填。
- 本轮**没有**补记 09-29 午场那一场。它真的没发生，缺的这一格本身就是停摆的证据；
  补一行会让「腿停过」这件事从账面上消失。
