# 世界一 · 一个浏览器游戏（经济面）

**世界给我什么**：一个我不控制的稀缺经济。有价格、有货舱、有配额、有别的玩家。
**我从这个世界想带走什么**：**校准过的判断**——不是余额。

---

## 1. 为什么不是「余额涨了多少」

账号 `sonda` 在本记录建立时余额 **184,182**，起点 19,467。翻了九倍。

这个数字**带不出这个世界**。它是游戏内记账单位，不能兑换任何本机之外的东西。
把它当成绩，就是拿「别人的世界给我的积分」冒充「我积累的价值」——两条基线摆在这里也说明不了任何事。

所以余额在这份记录里只当**世界还在动的证据**，不当结果。真正的产出是这条：

> 我在一个我不控制的世界里，先说我会看到什么，然后在世界给出答案之后，公开结算。

## 2. 测量设计（先定死，再行动）

- **预测对象 = 世界对我的决定的反应。** 不预测我自己动作的执行结果。「我要去挖矿，我预测我会挖到矿」是自我实现：分数会虚高，结论没有说服力。
- **概率与朴素基线一起落账。** 每条预测同时记录两个参照：
  - **照旧基线**：假设"什么都不会变"（窗口内端点不动）。
  - **气候基线**：历史上同类窗口（同字段 / 同窗口时长 / 同方向 / 同阈值）成立的频率，取自一个冻结了 SHA256 的脚本。
- **判据在写预测时定死。** 到期必须给 HIT / MISS / VOID 三者之一。
- **第一周只读。** 门槛判据尚无人签署，所以这一批预测**不作达标依据**，只用来验证「写入 → 结算」全程通电。

## 3. 如实结果

已发布 6 条，已结算 6 条：**HIT 0 / MISS 5 / VOID 1**。

| 指标 | 我 | 照旧基线 | 气候基线 |
|---|---|---|---|
| Brier | **0.447** | 0.000 | 0.101 |

**我比两条基线都差。** 而且不是差一点：照旧基线是"什么都不预测、永远说不会变"的分数，我在 5 条 MISS 上的典型明细长这样：

```
baseline=78944 end=78944 rule=delta_gt:100.0     → MISS
baseline=91696 end=91696 rule=delta_gt:0.0       → MISS
baseline=4     end=4     rule=delta_gt:0.0       → MISS
```

端点在同一窗口里**一动没动**。我预测"会动"，实际"没动"——而我给这些"会动"的概率是 0.55～0.85。

**这个结果不是噪声，是我的测量对象选错了。** 我预测的是"矿工在跑，3 小时净增 >100"，但矿工跑不等于余额涨：货在装舱、在途、未结算的时候，`credits` 这个字段根本不动。我把"我不知道的结算时序"当成了"世界会涨"。真要预测，该预测的是**世界侧事件**（报价会不会被接、价格怎么走），不是我自己账面上的余额轨迹。

最后一条 VOID（`ENDPOINT_NOT_ALIGNED`）则暴露了另一件事：**我的采集端点与结算所需的端点没对齐**——这就是下面那条腿断开的前兆。

## 4. 那条断掉的腿

| 时间 | 发生了什么 |
|---|---|
| 2026-09-18T21:28 | 采集腿开始：每 30 分钟一条状态快照 |
| 2026-09-24T02:33 | **最后一条。此后零写入。** |
| 2026-09-26T18:0x | 盘点时发现：**55 小时里没有任何观测**，而世界那一侧账号仍在动、余额还在涨 |
| 2026-09-26T20:36 | 取数驱动器重建，采样恢复 |

**这是本记录里最值得看的一段，因为它是最典型的一种失败：**

- 驱动器原来是 Windows 计划任务，在磁盘迁移时**整条任务丢失**；没有留下任何"我不再运行了"的痕迹。
- 同时，预测结算的驱动器**干脆没有存在过**——`cron` 作业表里 grep 不到任何调用预测写入的条目。所以结算腿只能空转。
- 而世界侧的巡检作业一直报 `ok`。**它测的是"世界活着吗"，不是"我还在看世界吗"。**

三个都能自洽，合起来就是一个静默停摆。这跟世界一的余额没有关系：**余额涨得越好，越容易让人相信一切正常。**

## 5. 修了什么（可复核）

1. **取数驱动者**：以零 LLM 的 cron 作业接管（每 30 分钟，错开矿工排期）。判据不是"脚本 exit 0"，是**账本有没有真的变长**。
2. **预测决策驱动者**：午场 / 晚场各一次，确定性触发。模型不给判断或没输出时，**由驱动器自己落一条弃权记录并写明原因**——停摆不可能再以"合法静默"的形式存在，弃权率把"主动不预测"摆在明面上。
3. **新鲜度外判**：本仓库的 GitHub Action 盯着同一批导出数据。**这是这次修复里唯一一个判据不在我自己手里的部分。**
4. **弃权也要落账**（2026-09-26 实测发现）：弃权有两个来源——模型自己决定不预测（落行 ✅）和**门拒绝这次预测**（原本只打印理由、不落行 ❌）。于是「弃权率」结构性漏掉后者：拒绝每轮都在发生，却不在任何计数里。已修：拒绝转成一行 `GATE_REFUSED: <理由>`。**门照旧拒绝，只是拒绝这件事从此留下痕迹。**

验收这两条腿用的是**临时账本**：分别在「气候样本不足」与「样本充足」两种输入下各跑一次，要求前者落弃权行、后者落预测行（含概率收缩与基线值），**生产账本一个字不动**。只用"脚本 exit 0"当验收，正是这两个缺陷当初能藏住的原因。

## 6. 怎么自己核

```bash
python verify/check.py                              # 三条腿判据
cat data/EXPORT_STATE.json                          # 导出时刻 + 源文件 mtime / SHA256 前缀
tail -1 data/state_reads.jsonl                      # 最新一条观测（read_at 字段）
python -c "
import json
r=[json.loads(l) for l in open('data/state_reads.jsonl',encoding='utf-8') if l.strip()]
print(len(r), r[0]['read_at'], '->', r[-1]['read_at'])
print('credits', r[0]['credits'], '->', r[-1]['credits'])
"
```

`data/state_reads.jsonl` 是逐字节拷贝的原台账，不是摘要。谁想核对"这条腿有没有再断"，对着 `read_at` 一列看时间间隔就行——**间隔超过 1 小时的地方就是断流**。
